# Transmission LXC with Mullvad WireGuard

## Overview

Transmission runs inside a Proxmox LXC container. The container uses a Mullvad WireGuard profile as its only VPN layer.

```text
Transmission LXC
  -> WireGuard wg0
  -> Mullvad VPN server
  -> Internet
```

Tailscale, Headscale, and any separate WireGuard server are not required for this setup.

## Requirements

- Proxmox host with an unprivileged or privileged Linux LXC
- Debian or Ubuntu-based container
- Transmission daemon
- WireGuard tools
- Mullvad WireGuard configuration file
- Root access to the LXC

The LXC needs normal network access through its virtual Ethernet interface. No inbound VPN port forwarding is required for outbound torrent traffic.

## Proxmox LXC Network

Example conceptual configuration:

```text
Container: Transmission LXC
Interface: eth0
Address: <lxc-lan-address>/<prefix>
Gateway: <lan-gateway>
Bridge: vmbr0
```

Keep the LXC management address and gateway documented privately. Do not commit real addresses to a public repository.

Verify networking inside the LXC before enabling WireGuard:

```bash
ip -br addr
ip route
ping -c 3 <lan-gateway>
curl -4 https://ifconfig.me
```

## Install Packages

```bash
apt update
apt install -y wireguard wireguard-tools curl ca-certificates
```

Install Transmission separately if it is not already present:

```bash
apt install -y transmission-daemon
```

## Install Mullvad Profile

Copy the Mullvad-generated profile to the WireGuard directory:

```bash
install -d -m 700 /etc/wireguard
install -m 600 <mullvad-profile>.conf /etc/wireguard/wg0.conf
```

Profile shape should resemble this, using values generated by Mullvad:

```ini
[Interface]
PrivateKey = <mullvad-private-key>
Address = <mullvad-ipv4-address>/32
DNS = <mullvad-dns-address>

# Preserve LXC management traffic outside the VPN.
PostUp = ip route replace <lxc-lan>/<prefix> dev eth0

# Keep the VPN endpoint reachable outside the tunnel.
PostUp = ip route replace <mullvad-endpoint>/32 via <lan-gateway> dev eth0 onlink
PreDown = ip route del <mullvad-endpoint>/32 via <lan-gateway> dev eth0 onlink 2>/dev/null || true

[Peer]
PublicKey = <mullvad-server-public-key>
AllowedIPs = 0.0.0.0/0
Endpoint = <mullvad-endpoint>:51820
```

Use IPv6 entries only when IPv6 is enabled and working inside the LXC. A profile containing IPv6 addresses can fail to start on hosts with IPv6 disabled.

Do not commit the profile. It contains a private key and should remain local to the LXC.

## Start WireGuard

Test manually first:

```bash
systemctl start wg-quick@wg0
systemctl status wg-quick@wg0 --no-pager
wg show wg0
```

Enable persistence after the tunnel works:

```bash
systemctl enable wg-quick@wg0
```

Expected healthy state:

- `wg-quick@wg0` is active
- `wg show wg0` reports a recent handshake
- Received transfer bytes increase
- The public IP belongs to Mullvad
- LAN SSH access remains available

## Remove Conflicting VPN Clients

Only one VPN layer is needed. If Tailscale was previously installed:

```bash
systemctl disable --now tailscaled 2>/dev/null || true
apt purge -y tailscale
rm -rf /var/lib/tailscale
```

Remove old WireGuard systemd overrides that require Tailscale:

```bash
rm -f /etc/systemd/system/wg-quick@wg0.service.d/override.conf
systemctl daemon-reload
```

Remove stale policy routing left by an interrupted `wg-quick` stop:

```bash
ip rule
ip rule del lookup 52 2>/dev/null || true
ip route flush table 52 2>/dev/null || true
```

## Verify VPN Egress

Run these commands inside the Transmission LXC, not on a workstation:

```bash
curl -4 https://ifconfig.me
curl -4 https://am.i.mullvad.net/connected
wg show wg0
ip route get 1.1.1.1
```

The Mullvad connectivity endpoint should confirm the active Mullvad server. The public address should differ from the normal ISP address.

Verify Transmission itself is active:

```bash
systemctl is-active transmission-daemon
ss -lntup | grep transmission
```

Transmission runs directly in the LXC, so its outbound traffic follows the LXC routing table and uses `wg0` when the full-tunnel profile is active.

## Speed Tests

Run tests from inside the LXC. Use the same download size and repeat each test several times when comparing Mullvad locations.

```bash
curl -4 -o /dev/null -sS \
  -w 'time=%{time_total}s speed=%{speed_download} B/s\n' \
  'https://speed.cloudflare.com/__down?bytes=50000000'
```

Convert bytes per second to megabits per second:

```text
Mbps = speed_download * 8 / 1000000
```

Check latency separately:

```bash
ping -c 10 1.1.1.1
```

For reliable comparisons:

- Run each test at least three times.
- Compare servers at similar times of day.
- Use the same download size.
- Record average speed, latency, and packet loss.
- Test torrent performance separately from HTTPS throughput.

## Troubleshooting

### No handshake

```bash
wg show wg0
ip route get <mullvad-endpoint>
journalctl -u wg-quick@wg0 --no-pager -n 50
```

The Mullvad endpoint must route through the LXC gateway, not through `wg0`.

### Internet unavailable

```bash
ip rule
ip route
curl -4 https://ifconfig.me
```

Check for stale policy rules or routes from an older VPN setup. Stop WireGuard before modifying routes:

```bash
systemctl stop wg-quick@wg0
```

### SSH access lost

Use the Proxmox console, stop WireGuard, and restore the normal LAN route:

```bash
systemctl stop wg-quick@wg0
ip link delete wg0 2>/dev/null || true
ip rule del not fwmark 51820 table 51820 2>/dev/null || true
ip rule del table main suppress_prefixlength 0 2>/dev/null || true
ip route flush table 51820 2>/dev/null || true
ip route replace default via <lan-gateway> dev eth0
systemctl restart ssh
```

### DNS failure

```bash
resolvectl status 2>/dev/null || cat /etc/resolv.conf
getent hosts example.com
```

Use the DNS server supplied by the Mullvad profile, or configure a trusted resolver appropriate for the deployment.

## Security Notes

- Never commit Mullvad profiles, private keys, preshared keys, auth tokens, or real infrastructure addresses.
- Treat a WireGuard private key as a password. Rotate it if exposed.
- Restrict Transmission RPC access to trusted management networks.
- Keep `/etc/wireguard/wg0.conf` mode `600`.
- Verify public IP from inside the LXC, not from the administrator workstation.
